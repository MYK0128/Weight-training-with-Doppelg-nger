# Muscle Quest MVP

週間メニューを組み、筋肉量の変化を追う Web アプリです。
`/plan` で種目・主部位・セット数を保存し、週あたりの部位別セット数と日数を確認できます。
筋肉量は実測の推移と、入力したペースを1か月から5年続けた場合のシナリオを分けて表示します。
`/dashboard` では従来の記録・アバター機能を使えます。

実測ペースは最新測定までの90日間に、28日以上にわたる3日分以上の測定がある場合のみ表示します。
7日以上離れた測定ペアから月換算の変化を求め、中央値を使います。
部位別セット数は筋肥大と関連する練習量の指標であり、個人の筋肉量の増分への換算には使いません。
参考: [週間セット数と筋肥大のメタ回帰](https://pubmed.ncbi.nlm.nih.gov/41343037/)、
[筋量関連指標の測定法比較](https://pmc.ncbi.nlm.nih.gov/articles/PMC6624257/)。

旧プランを開くとメニュー名と期間を引き継ぎます。旧プランの体重は筋肉量に流用しません。

既存環境を更新する場合は `npm run db:push` で週間プラン用のテーブルを追加してください。
デモデータの再投入は不要です。

## 1. システム概要

Muscle Quest は、以下の 3 つのレイヤーで構成するシンプルなフルスタック Web アプリです。

- フロントエンド: ユーザー登録、ログイン、筋トレ記録、身体情報記録、ダッシュボード表示
- アプリケーション層: 認証、記録保存、アバター成長計算、成長率比較
- データ層: SQLite にユーザーごとの筋トレ履歴、身体情報、アバタープロフィールを保存

MVP の中心体験:

- 現実の筋トレ記録を保存できる
- 身体データを保存できる
- 保存されたデータからアバター成長パラメータを算出できる
- 現実の成長率とアバター成長率を比較ダッシュボードで可視化できる

## 2. 使用技術の提案

今回の MVP では、立ち上がりの速さと保守性を優先して以下を採用しています。

- フロントエンド: `Next.js(App Router) + React + TypeScript`
- バックエンド: `Next.js Route Handlers`
- DB: `SQLite`
- ORM: `Prisma`
- グラフ: `Recharts`
- バリデーション: `Zod`
- 認証: 独自のシンプルな Cookie Session 認証

この構成の理由:

- Next.js 単体で画面と API を同居でき、MVP の開発速度が高い
- Prisma により、将来的な PostgreSQL などへの移行がしやすい
- App Router により、ダッシュボードのサーバーサイド取得と UI 分離がしやすい
- アバター成長ロジックを `lib/avatar.ts` に閉じ込めているため、将来 3D 表現や装備要素を追加しやすい

## 5. API 設計

### 認証

- `POST /api/auth/register`
  - 新規登録
- `POST /api/auth/login`
  - ログイン
- `POST /api/auth/logout`
  - ログアウト

### 記録

- `POST /api/workouts`
  - 筋トレ記録を追加
- `POST /api/body-metrics`
  - 身体情報を追加

### ダッシュボード

- `GET /api/dashboard`
  - 比較ダッシュボード用データを取得

レスポンス例の考え方:

- 認証 API は `ok`, `user`, `error`
- 記録 API は保存結果のオブジェクトを返却
- ダッシュボード API は `summary`, `chartPoints`, `avatar`, `workouts`, `bodyMetrics` などを返却

## 6. アバター成長ロジック案

MVP ではわかりやすさ重視で、以下のルールを採用しています。

### 基本ルール

- 筋トレ 1 件ごとにボリュームを計算
  - `volume = weightKg * reps * sets`
- ボリュームに応じて経験値を加算
- 部位ごとに対応するアバターステータスを上昇

### 部位対応

- `CHEST` -> `chestStat`
- `ARMS` -> `armStat`
- `LEGS` -> `legStat`
- その他部位 -> `enduranceStat`

### 見た目成長

胸・腕・脚のステータスをそれぞれ SVG の胸幅・腕幅・脚幅へ反映します。
身体測定がなくてもトレーニングだけで見た目と Body Shape Score が成長します。
描画寸法には上限を設けています。

- 体重増加
- 筋肉量増加
- 胸囲、腕囲、脚囲

これらをもとに `bodyShapeScore` を算出し、一定値を超えるごとに `visualTier` を上げます。

### レベルアップ

- 経験値に応じてレベル上昇
- `sqrt` ベースの緩やかな成長曲線を採用し、序盤は成長を体感しやすくしています

### 比較表示

グラフはすべて変化率（%）に揃えます。体重・筋肉量は初回の有効な測定値、
アバターは初期値10を基準にします。未測定は0%ではなく欠測として扱います。
重量変化率は、別の日にも記録された同じ種目の初日・最終日の最大重量を比較し、
比較可能な種目の変化率の平均を表示します。比較できる種目がなければ「比較待ち」です。
体重の増加は筋肉の増加を意味しません。

連続記録日数は日本時間の今日または昨日から続く日数です。
最終記録が一昨日以前なら0日になります。未来の記録は日数に含めません。

- 現実の体重成長率
- 現実の筋肉量成長率
- 扱う重量の伸び率
- Avatar Power 成長率
- Avatar Visual 成長率

## 8. MVP 実装手順

1. 依存関係をインストール
2. `.env` を作成して `DATABASE_URL` を設定
3. `prisma db push` で DB を作成
4. `prisma/seed.ts` でダミーデータを投入
5. `npm run dev` で起動
6. デモアカウントまたは新規登録でログイン
7. 筋トレ記録と身体情報を登録し、ダッシュボードで成長を確認

起動コマンド:

```bash
cp .env.example .env
npm install
npm run db:push
npm run db:seed
npm run dev
```

## 実装メモ

記録保存とアバター更新は同一トランザクションで実行し、片方の失敗時は両方を取り消します。
既存の記録にも新しい成長ルールが適用されるよう、ダッシュボード表示時に再計算します。
`npm test` で成長計算・連続記録・一時SQLite DBでの保存取り消しを検証できます。

- UI は「モダンな筋トレアプリ x ゲーム HUD」の中間を意識して設計
- コメントは複雑度の高い箇所を中心に最小限で付与
- アバター表現は今は SVG シルエットだが、将来差し替えしやすい設計
- ダミーデータを投入すれば、画面遷移と主要機能をすぐ確認可能
